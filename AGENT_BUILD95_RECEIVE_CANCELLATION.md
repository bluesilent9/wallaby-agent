# Development Build 95

Direct wallet exports now send an authenticated stream-close notification on completion and failure. Local bridge failures also close the remote stream. A failed source export therefore wakes the receiver instead of leaving its authorisation waiting until the source workspace closes. Opening a wallet stream has a bounded 20-second handshake.

Cancel receiving stops the selected incoming transport, clears its selection and review, and releases the batch when its worker exits. A stale review identifier can still cancel the active receiving batch. If a Core import is already executing, the Agent retains its operation reservation until that import reaches its normal safe checkpoint. Completed imports are retained; cancellation does not claim to undo them or terminate Core.

Read-only watch/history export preparation no longer marks a transfer attempted before data is sent. Source logs distinguish incomplete archive coverage, catching-up Core, changed archive history and unavailable pruned blocks. They include a fixed stage, installed module/line and exception type without dumping wallet data or exception contents.

An approved transfer between directly paired Agents accepts the source's complete stored Extinct snapshot. When the source lacks a local historical-scan receipt, the current direct history format records `trusted_direct_snapshot` provenance inside the receiver's Core archive. It does not claim that the receiver independently rescanned historical blocks. This provenance survives another transfer and subsequent extinction additions. Transaction records, labels including LOST information, exact address/transaction inventories and active-chain confirmation metadata are checked before the archive is accepted. A conflicting active local owner still blocks import, and recipient-only legacy entries are never silently certified or discarded.

No historical blockchain download or rescan is triggered solely by this trusted archive transfer. Nodes still need a compatible validated chain; ordinary block catch-up requires the source to retain the receiver's missing range. The source's existing 51 transaction records cannot establish whether some older transaction was omitted by a past upgrade. The direct transfer accepts the trusted source's stored inventory under the explicitly requested trust model; it cannot invent missing records.

Checks exercise failed-source stream closure, cancellation without closing the other Agent, reservations during Core work, grouped transfers, ordinary private/watch wallets, multisig restoration, complete Extinct history and LOST labels. A real Core integration mines and validates history on both nodes, prunes the old full blocks on both, demonstrates that the old headers remain readable while the full blocks do not, then transfers the old transaction history without a rescan. Malformed records and active ownership still fail. Browser checks cover the Cancel receiving action under the production content-security policy.

Final validation: 49 checks passed against isolated Bitcoin Core 31, including both-node pruning and the failure/cancellation cases. Both production-CSP browser suites passed; the receiving review screenshot was inspected. Installer/source parity and root ownership/permissions are checked by the release exporter.
