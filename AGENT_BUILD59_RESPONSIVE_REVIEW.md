# Build 59 — policy review without blocking the workspace

Treasury Russia's sanitised diagnostics showed three local reviews taking approximately 81–83 seconds. Review held the exclusive workspace lock while checking local descriptor matches and performing Core's full UTXO scan. Public inventory returned workspace_lock_timeout, and the protected HTTP status call could time out and substitute an unavailable-worker response. That made a live protected window temporarily look disconnected. After Dashboard cancellation arrived, an idle pending builder_cancel also suppressed all public inventory indefinitely.

Policy refresh and policy-refresh cancellation reviews now execute as one bounded background job per protected worker. Repeated UI polls reuse that exact job; they do not restart the scan. The protected review pane shows checking status and elapsed time, then renders the independently verified facts. A changed or withdrawn request cannot return a successful review. The ten-minute approval review lifetime starts after the local verification completes. Failures expose only sanitised diagnostics; retrying a failed read-only review remains an explicit user action.

The background job does not hold the workspace lock across Core's long scan. Status and the existing allowlisted public RPC inventory remain available. Mutating wallet/disc actions are refused until review finishes, and workspace closure remains blocked. Pending idle cancellation/destruction checklists permit public inventory while retaining their existing private-operation and safe-close guards.

Protected status also retains its last protected snapshot if another exclusive operation owns the lock, marked status_pending and busy, with current connection flags. A temporary local lock no longer falsely reports that the worker/viewer disappeared. No new Dashboard capability or message kind is required; Dashboard 80+ remains the grouped-refresh minimum. Build 83's existing handoff is compatible.

The replacement-disc progress review remains accessible for awaiting_backups rows after initial approval. Full verification, refreshed signer requirements and explicit old-disc destruction confirmation remain mandatory; other archive wallets stay optional and omissions are listed.

No scan is skipped, funds are not assumed absent, no key generation/signing is replayed, and no wallet is deleted by this responsiveness fix. Finish or reconcile the existing protected work before updating. For an already running Build 58 worker, use its existing local cancellation API and bounded read-only diagnostics; do not restart a protected service containing unfinished work.
