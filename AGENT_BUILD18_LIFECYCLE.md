# Build 18 worker upgrades and protected windows

Build 18 checks the protected worker's own build/protocol before ui.arm or node startup. An upgrade does not assume installed Python files replaced an already running interpreter. A responding current worker is reused. An idle older worker is gated closed, stopped through its fixed service and verified to have empty protected RAM, then started once and version-checked again. There is no restart loop or repeated privileged prompt.

Build 17 workers implement the atomic safe-close gate. Earlier workers explicitly rejecting that action are inspected inside their own protected service: the installed viewer runs a bounded inspection instead of opening Qt. Only a fresh nonce/PID/start-time-bound idle boolean crosses back. Private pending/setup/archive/outbox state stays protected. Loaded/staged archives, active work, pending authorisations or critical results retain the older RAM. Optional sync/signing denial/background notifications do not count as unfinished results. Retirement outcome/cancellation delivery is critical because Dashboard must track it; its RAM result is retained until acknowledged. The persistent wallet-sync Denial list remains an intentional preference, not unfinished work. Unsupported/protection/timeout errors cannot be interpreted as an idle workspace.

An older worker retaining work can be opened with the Services recovery button. The ordinary sidebar never launches a protected window. A legacy viewer can check its own protected state before native close when the older worker lacks the new close action. Other close errors display their actual bounded local reason instead of pretending every failure is unfinished wallet work. The monitor observes legacy viewer exit as well as current window-required flags. Upgrade locking prevents a probe's temporary viewer from triggering normal close cleanup; a stale marker is removed only when no upgrade lock is held.

Only Services is selectable in the ordinary window. The first successful Core/Dashboard node connection automatically opens the protected window and makes the ordinary page inert. Only Services is disabled in the protected window. Protected-processing evidence is displayed there, outside the hidden Services fieldset. Confirmed close switches off only the node and clears idle protected workers; DDNS-GO and Dashboard tunnels/settings remain independent. Secret operations and critical undelivered results still block cleanup. Disabled wallet-sync policies are intentional preferences, not unfinished work.

No protection, dump/swap restriction, pruning setting or SSH server configuration is relaxed. The wallet-deletion helper added for locally approved extinction is a separate unprivileged service with a restricted operation; the protected Bitcoin worker's persistent filesystem remains read-only.
