## Deployment limits

Dashboard V1 Build 10 supports Build 8 synchronization and the retirement proposal. The future Wallet Builder, Agent identity exchange, authenticated contributions, complete-policy review, per-role disc proofs, final completion delivery and shared-policy inventory require [DASHBOARD_BUILD9_UPDATE.md](DASHBOARD_BUILD9_UPDATE.md). No Dashboard code is changed here.

Privileged protected-workspace startup, logind/polkit permissions, per-service AppArmor, Qt WebEngine sandbox/desktop startup, Snap mount-namespace/confinement and real optical drive/M-Disc burning have **not** been exercised on the user's machine. Sandbox restrictions prevented a meaningful systemd unit verification run. Do not treat a passing isolated suite or package build as proof of those deployment controls. Actual peer laptops, native password dialogues, firewall/modem reachability and a full mainnet redownload remain deployment checks.

The physical-only storage boundary concerns new private keys and backup staging within the controlled RAM workflow. Existing on-disk data cannot retroactively become never-on-disk. Intentionally retained encrypted Core node wallets, public monitors/blockchain, relayed public information, service configuration and machine SSH identity retain their chosen persistent destinations. A trusted operating system, administrator, dependencies and hardware are assumptions. No independent security audit has been performed.

Pruning mode and limit are never changed. No additional automatic safety backups are made. Failed or uncertain wallet installation/burn operations are not automatically repeated. Power loss/reboot discards unfinished volatile state; reconcile existing Core wallets and server public audit before a deliberate fresh request.

No production Core, installed Agent service, real user wallet, Dashboard, SSH listener, firewall or optical medium was altered during these checks.
