# Build 102 — Internal staging wallets cannot shadow Extinct

Build 101 loaded retained .wallaby-history-<24 hex> directories during inventory. An alphabetical descriptor deduplication could retain the staging copy and omit the real Extinct alias. The stage then failed ordinary source selection because its descriptors also matched the real archive. The new preview diagnostic identified peer_wallet:111 in the supplied log. Meanwhile Extinct could remain visible only as a grey advisory Server hint. That row had no executable direct route to select.

Build 102 excludes exact reserved history-stage, policy-monitor and signing-account names before direct inventory loading/deduplication. Source offers and receiver offer handling also exclude them, and advisory/table presentation suppresses stale internal rows. These folders are retained without alteration. Their contents remain available for explicit local recovery; they are never automatically treated as the live archive or merged into it.

Extinct export selects the exact single archive alias instead of treating identical staged descriptors as another source wallet. Public detail collection ignores internal copies, preventing stale staging labels from contaminating the real archive review. Multiple genuine Extinct aliases still require local reconciliation. Actual combined multisig/vault wallets remain available for their permitted public-policy sync; no signer-secret cloning permission changes.

The regression creates a retained staging wallet with identical descriptors but different labels before the real archive. It verifies that discovery offers the actual Extinct archive, selection survives three consecutive inventory exchanges and creates an Authorise group, native history transfer succeeds, LOST labels come from the live archive, and the retained staging folder and its labels remain unchanged. Further tests cover ordinary private wallets, multisig/current-and-old vault policies, pruned-node archive updates, persistent denials, advisory hints, and safe workspace closure. Production-CSP UI regression checks the existing grey/green/red receiver controls and approval flow.

Both Agents should be updated. The companion Server fix must exclude the same internal names before its advisory inventory deduplication and publication. Agent Build 102 already ignores such hints from an older Server, but it does not change that Server's inventory or data. No profile reset or wallet deletion is required.
