# Build 34: local vault estimates and Authorise ordering

Wallet Builder initial participation and final policy approval now show the Agent’s own rough vault unlock estimate in UTC and the machine’s local time zone. Additive vault policy refresh also shows it. Existing transaction reviews keep the same estimate. Estimates use local Bitcoin Core block-header timestamps, including on pruned nodes, and never use Dashboard forecasts or online data. The first eligible spending block is height + 1. An unavailable header or mismatched proposed network produces an explicit unavailable notice. The date is advisory and kept outside immutable approval facts, so changing estimates do not alter policy verification.

Authorise keeps pending requests, the selected review and local wallet cards above all denial sections. Persistent wallet-sync exclusions, obsolete Extinct child denials and session declines appear at the bottom. Existing enable/delete/clear actions and persisted preferences are unchanged. Disabled requests are not unfinished authorisation work.

Validation: 17 focused Python tests passed, including real Bitcoin Core 31 initial/final 2-of-3 vault setup, policy refresh, changing advisory estimates during approval, estimator unavailable/wrong-network cases and startup authorisation. All 14 JavaScript suites and web syntax checks passed, including actual initial/final/refresh rendering and denial ordering/control regressions. The package export compares installed source, web, helpers and documentation with the source tree. No Dashboard protocol change is required. This is V2 Development Build 34, not a Stable release.
