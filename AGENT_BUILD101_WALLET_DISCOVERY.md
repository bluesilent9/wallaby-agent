# Build 101 — Exact direct wallet discovery and advisory Server hints

Build 100 could discard an Extinct offer when source preview preparation failed transiently, while another managed policy row appeared green without a usable route. Source discovery now waits briefly for competing local inventory reads, prepares Extinct first, retains authenticated missing-wallet discoveries while previews are retried, and logs fixed preparation phase and source location if a preview fails. A redundant reserved policy-monitor wallet is omitted when another wallet in the source inventory covers its complete descriptors. Source wallet contents are still checked independently before export and receiving approval.

Grey rows indicate Server-only observations or direct sources whose preview is not ready. Green requires a pending executable route bound to a currently usable direct Agent connection. Local denials always remain red and persist when a source disappears. Server-only hints can be denied without pairing but cannot be selected, reviewed as transfers, imported, or used to supply permissions. A verified direct offer takes precedence over the same advisory policy. Extinct uses one stable whole-archive identity across aliases and history growth.

Server Build 19 intentionally omitted all wallet offer snapshots, so the companion Server update must restore advisory-only wallet_sync_offers snapshots with source_online=true for currently connected sources. Withdraw on source disconnect and keep refreshing full snapshots. Agent ignores hints without explicit online presence, expired after 45 seconds without a snapshot, or marked peer_offline/invalid_pair. It still ignores Server executable transfer queues, requests and previews in direct discovery mode. Server labels and descriptors remain untrusted display information.

Tests cover temporary inventory contention, Extinct denial/re-enable and preview retry followed by actual receiving, native updates between pruned Core nodes, missing transactions with identical addresses, LOST labels, archive growth, single-signature private receiving, old/current vault policies and multisig public receiving. Additional checks ensure live hints remain advisory, disappear on disconnect/expiry, cannot become direct authority, and cannot withdraw direct offers. Production-CSP browser checks cover grey/green/red styling, disabled hint controls, local denial action, grouped Authorise approval, cancellation and protected-window cleanup. No physical production wallet or user node was used in tests.
