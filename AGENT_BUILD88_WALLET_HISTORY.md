# Build 88 — local wallet cards, history and retirement

Authorise refreshes its loaded Core wallets on entry and after authorise actions. The manual Refresh wallets button is removed. Concurrent listing requests are coalesced; a refresh requested during another listing replaces its stale result. Cards have distinct randomly seeded session colours. Clicking a card opens its history. The separate delete bin appears on hover or keyboard focus and remains visible on touch devices. The explicit local Yes/No deletion review remains.

The transaction dialog uses this node's recorded Core transactions, public descriptors and address ownership. It never requests private descriptors or initiates a rescan. Newest transactions come first. Columns are UTC date, UTC time, address, signed Bitcoin Pipe amount and running balance. Fees are deducted once. Pending and immature rewards are included; conflicted/abandoned transactions are excluded. Rows turn green/red with their signed net movement. A self-transfer shows its net fee. Multiple outgoing addresses have a tooltip with copy controls. Clicking the table toggles all groups to transaction IDs; copying does not toggle. Reopening resets to addresses. Outside click and Escape close the dialog. Text is non-selectable, with deliberate copy controls; clipboard paste/read permission remains disabled in the protected viewer.

Extinct wallets retain their Core labels and LOST metadata unchanged. History headings use the original wallet label before its separate LOST suffix. Each group's recorded inputs/outputs determine its signed movement and running balance. Groups are ordered by newest transaction. Missing historical transactions are not invented and this view does not certify archival completeness. The table refuses oversized inventories rather than displaying misleading partial running balances.

Retirement deletion no longer requires a paired Agent. Full local Extinct readback remains mandatory when the preserved local archive is loaded. With no available local copy, the existing signed preservation receipt and current local wallet checks remain, and the user receives the preservation-elsewhere warning. Merely having an unloaded archive on disk no longer blocks this reviewed deletion. A loaded unrelated/empty wallet cannot suppress the warning. Known mismatched local data, invalid signatures, changed original policies, funded/locked wallets and changed file identity still block retirement deletion.

A connected Build 88 Agent can provide optional public Extinct comparison evidence over its authenticated direct Agent stream. This feature is advertised only in authenticated peer ping messages; older peers are not probed. The source compares every supplied address/label and raw transaction hash with its private-key-disabled address-only Extinct wallet, including confirmation in its active chain. Only counts and bounded matching examples return. Mobile and relay routes cannot serve it. Concurrency, sizes and time are bounded. Missing, busy, incompatible, disconnected or mismatching peers leave the preservation warning and never become a deletion gate. This comparison does not import, sign, erase, or approve anything.

No Wallet Server update is required. Optional peer evidence requires Build 88 on the peer as well. Existing paired identities and other direct confirmation checks remain.

## Validation and limits

Tests use isolated Bitcoin Core 31 regtest nodes and real paired SSH streams. They cover ordinary wallets, exact fees/balances, multiple recipients, self-transfers, immature rewards, Extinct group balances and LOST preservation, mismatch/older-peer/disconnection outcomes, deletion without a peer, and protected local API routing. Existing retirement evidence, missing-signer multisig extinction, receiver-initiated wallet transfers, chain recovery/cloning, startup/session ownership and diagnostic privacy regressions are retained.

A headless Chromium browser exercises the actual HTML/CSS/scripts with synthetic local API responses: hover delete, click separation, immediate/entry refresh, signed/grouped history, address and TXID clipboard writes, mode toggling, default reset and outside/Escape close. The browser fixture does not claim a physical laptop/Qt desktop end-to-end run. Core/SSH tests use temporary data and test-only native helper replacements, not production wallets or password dialogs. The package is extracted and compared with every runtime source/web file and installed document; root ownership and protected modes are checked.
