# V2 Development Build 6 validation

Validated 29 October 2026. Target: Ubuntu 26.04 LTS amd64, Bitcoin Core V31. 77 automated tests pass, including the twelve Core regtest cases. Full test output and package verification accompany the installer.

Build 6 removes ping completely. The per-user monitor owns an authenticated IPv6 OpenSSH master with strict host-key verification, key/agent authentication, keepalives and bounded retry backoff. DDNS-GO, Dashboard and node workers add/cancel IPv6 loopback forwards through that socket. Each master generation gets a different private socket, preventing stale workers from treating a replacement login as an existing forward. Service toggles never create another SSH login. Saved SSH changes or Connect replace/retry the master; unrelated RPC changes leave it intact.

A live test against the user's already configured server authenticated a master with no forwards, added DDNS-GO and Dashboard forwards on temporary local IPv6 ports, received HTTP 307 and HTTP 200 respectively, cancelled both, and verified the original master PID was still authenticated. The isolated connection was closed afterward. No server settings, installed Agent units, production tunnel ports or saved user config were modified.

Browser regression testing used an isolated configuration/runtime directory. A plain local URL without a fragment successfully loaded the saved hostname, username, port and switches. Editing username/port wrote config.cfg without Save; external file changes appeared on reload/poll. The Connect label and removal of the old Utilities access warning/Save button were verified. The preview was then linked to a real isolated shared-master monitor (unit-manager calls stubbed to protect installed services); screenshot shows authenticated SSH green with all three service switches OFF. Production startup/session-manager refresh is covered by mocked lifecycle tests; installation on the user's laptops remains pending.

The local-page handshake requires same-origin Fetch Metadata and a custom header, exact loopback Host/Origin and no CORS access. Application APIs still require the ephemeral Bearer token. Cookies are deliberately not used because they are not port-isolated. Fresh tabs and daemon-token refresh no longer depend on URL fragments/sessionStorage. Controls are disabled until saved state loads. Valid partial edits are atomically saved after 350 ms; invalid drafts do not overwrite valid configuration. Config reload/client invalidation and old-process refresh after upgrade are tested.

Existing tests retain public/read-only direct Dashboard RPC enforcement and twelve isolated official Bitcoin Core 31 regtest scenarios: full sweeps, immutable signed export without broadcast, local broadcast/relock, input changes, address-only/public-key watch destinations, forged amounts/weak sighashes, approval/denial persistence, matured withdrawal/rollover and wrong-passphrase retry before any signing call. Test Core nodes use temporary data/test coins with external P2P disabled. No real Bitcoin signing or broadcast occurred.

Package inspection verifies version/amd64 architecture, native PIE launcher, all five user units and shared-master dependencies, complete runtime/web parity, bundled map/licenses, no Python caches or user data, and no tunnel activation in package scripts. Build 5 vault/authorisation protocol remains unchanged. Future Dashboard exchange and Stage 2 receiving implementation, cross-machine end-to-end sync, and production desktop login/startup validation remain pending. Development only; no independent security audit or Stable release.
